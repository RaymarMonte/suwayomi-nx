What the two S3 hits are (checked in the disassembly, 2026-10-25):

1. apmSetPerformanceConfiguration, called only from libnx's appletInitialize.
   libnx calls it only for applications, and only for an entry of the weak array __nx_applet_PerformanceConfiguration[2]
   that is non-zero ("ldr w1, [x3, x2, lsl #2]; cbnz w1, <call>"). The default array is libnx's, in .bss, so all zeros:
   the call never runs unless our code defines that array. It is linked in only because the code path exists.

2. lblSetCurrentBrightnessSetting (rule lblSet*), called only from brls::SwitchPlatform::setBacklightBrightness(float).
   That's a virtual function, so the linker keeps it even though nothing calls it: borealis never calls
   setBacklightBrightness itself (only its platform classes define it), and our code doesn't either.

So neither runs today. Both are in the binary, so a strict gate would fail every build. The choice of how the WP-03b gate
handles them is recorded in DECISIONS.md (D28).

S2: no fatalThrow* in the binary. Crash hooks: libnx's default diagAbortWithResult is linked, __libnx_exception_handler is
not linked at all. Both are expected until WP-03b adds our own (S1).
